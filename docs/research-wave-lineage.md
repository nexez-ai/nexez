# Bounded protocol-4 continuation

This is opt-in preparation. The migration creates no run, links no cohorts,
changes no live limit and does not import or activate the frozen extension.
The stopped 5,000-result quality, usage, billing and customer-pressure gate
still comes first. Superseded protocols and smoke remain excluded.

## Continuity and duplicate handling

A reviewed root can be sealed only while already stopped with no target or
dispatch leases. It records a one-way marker of the runtime domain-hash
configuration and finite family attempt/dispatch limits. Before setting it,
the operator must verify continuity with the existing observations and deployed
configuration. A marker generated today alone does not prove historical continuity.
After sealing, the fingerprint and family bounds cannot change, the budget or
deadline cannot increase and the frozen source cannot be rewritten.

The authenticated internal status response reports runtimeHashIdentityFingerprint,
computed through the same hash function using a fixed reserved .invalid marker.
It never requests that marker over the network and never returns a salt or
website identifier. Before claiming a batch, a sealed run compares its stored
fingerprint with the runtime value. A mismatch pauses the run before site traffic.
The page scanner, eligibility, score and domain-hash algorithm are unchanged.

Each root permits exactly one continuation, no branches or chains. The parent
must be exhausted with no remaining queued/running targets or live dispatches.
Both waves use protocol 4 and the identical sealed fingerprint. The extension
must retain the same source extract, mapping, selection seed and original frame
checksum. Parent and child cannot run in parallel. Once linked, the parent
cannot resume or change its usage/cost counters.

An indexed identity_cohort on results equals the observation's original cohort
unless it belongs to an explicitly linked continuation. The continuation uses
its parent's identity namespace. A unique namespace/final-domain-hash index
therefore rejects duplicates across both waves atomically. The existing fenced
completion function records these conflicts as duplicate_final_domain, not a
zero score or a second result. Observation cohort, metadata and original target
remain unchanged. Earlier protocols keep their own namespaces and are not
silently reclassified. Initial-domain overlap is rejected during child import.

## Shared bounds and cost carry

Schema family ceilings are 150,000 total attempts and 25,000 total dispatches,
but the operator must choose the smaller reviewed bounds justified by the
stopped checkpoint and USD 100 total ceiling. Once sealed, do not expand them.
Choose a root target_successes/checkpoint that does not truncate at 50,000.

The parent's recorded usage consumes the family's attempt and dispatch bounds.
The child's own caps cannot exceed the remaining allowance. The child's base
reserve must include the parent's complete cumulative reservation, rounded UP
to whole cents, and its budget/deadline cannot exceed the parent's. The existing
dispatch ledger keeps all old rates and adds only future charges at the active
prospective rate. The trigger rejects attempts to detach the child, reset usage,
erase reserves or extend the family budget/deadline. No new USD 100 allowance.

study_family_status(root) reports combined attempts, dispatches, unique results,
active waves and cumulative reservations. It uses the child's carried total
when present, not a sum that double counts the parent's reservation. Individual
cohort statuses remain wave-local and must not be mistaken for the study total.

## Activation checklist

1. Pass the stopped 5,000 gate and verify actual deployment, hash configuration
   history and a private equality check against recorded final-domain hashes.
2. Recalculate a conservative finite family bound from the actual cumulative
   ledger, all non-compute costs, billing lag and original deadline. Document
   intermediate quality/cost checkpoints and preserve every qualifying result.
3. Seal only the root's new lineage fields while stopped. Keep its existing
   frozen manifest intact. Any limit/rate change is a separate reviewed action.
4. Continue the original frame first. Do not create the extension until the
   parent is exhausted and all leases are inactive.
5. Initialize the child in preparing state with continued_from, matching sealed
   identity/bounds, protocol 4, the complete rounded-up cost carry and remaining
   attempt/dispatch limits. Use the existing audited extension manifest. Then
   import and verify all 50,000 disjoint additions and hashes before freezing.
   The generic importer does not create these lineage fields automatically;
   preinitialize the guarded row before invoking its resumable batch path.
6. Activate only the reviewed next checkpoint. Keep one wave active and preserve
   the original deadline, quality rules, robots, SSRF, privacy and customer headroom.

The original frame is scanned before the extension. A bounded partial two-wave
result is not a single random prefix of the 125,000-candidate nested frame.
Report this limitation, the actual qualifying denominator and all exclusions.
